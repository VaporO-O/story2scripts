## 产品定位与操作路径

Story2Script 是“小说 → 结构化剧本 → 审校与改写 → 版本采用”的创作工作台。面向长文本小说，使用稳定人物 ID、结构化场景、原文证据和剧情事件账本维护连续性。

常见路径：导入小说 → 预览章节 → 选择改编类型及本地/AI 模式 → 生成剧本 → 分场预览或 YAML 编辑 → 局部润色/剧情联动 → 检查 → 下载或采用。AI 功能需配置兼容的模型服务，本地转换、演示审校和确定性规则不需要模型调用。

## 已实现能力

| 模块 | 当前能力 | 使用与限制 |
| --- | --- | --- |
| 小说导入 | 文本粘贴、TXT/TEXT/MD/MARKDOWN/CSV/LOG、EPUB；中文编码处理、章节预览 | MOBI/AZW/AZW3 提示先转格式；尚无 DOCX/PDF 导入与 OCR |
| 改编类型 | 短剧、影视剧、舞台剧、广播剧、分镜脚本 | 另有幕/集组织层、分组建议和目标分钟数；目标不等于估算片长 |
| 全文转换 | 本地规则转换及 AI 分块转换；支持单章、多章和无标题正文；全局人物、地点和时间线；前文检索；结构归一化和校验 | 空文本或只有章节标题时拒绝；失败片段可能跳过并返回警告，需核对完整性 |
| 生成进度 | 持久化任务、阶段进度、转换场景流式预览、重试/失败提示；创作 AI 后台任务与恢复；落盘后发布状态、可选请求去重 | 默认本地线程池；可选 Redis/Celery 同主机多进程，仍不支持跨机器业务数据库 |
| 剧本编辑 | 分场预览、YAML 编辑校验、场景内联编辑、自动保存和草稿历史；YAML/TXT/HTML/Word 导出、HTML 打印 | 正文修改标为待核验；PDF 使用浏览器打印，尚无后台直接 PDF 导出 |
| 场景结构 | 场景标题、内外景、昼夜、地点、实际在场角色、道具、目标、冲突、节拍、潜台词、戏剧化决策、镜头提示 | 导出可附人物表及场景/道具表；尚无成本预算或片长自动估算 |
| 人物小传 | 本地/AI 提取定位、性格、目标、关系、出场章节、关键变化；稳定 ID 与别名 | 创作面板可按场景时点查看关系、拖拽/缩放、角色筛选和证据跳转；无动画推演 |
| 对白归属 | 多轮对白、听话人与说话人区分、后置言说标签、短回答、长对白；明确原句证据可纠错 | 模糊代词和复杂别名仍有语义不确定性，不能宣称全书准确率 100% |
| 局部润色 | 改对白、加强冲突、短剧节奏、镜头提示、减少旁白、人物语气；自然语言聊天入口 | 已有事件账本时，AI 局部润色重新提取并校验，必须保持该场末状态 |
| 审校 | 本地/AI 四维评分、阈值裁决、有限轮自动修正；逐场人审和报告合并、下载 | 本地启发式分数与 AI 分数不可直接等同；文学质量需作者判断 |
| 故事检索 | 词法、Embedding、RRF 混合检索，可选模型重排；SQLite/`sqlite-vec` 持久化片段和向量；原文摘录窗口、章节截止过滤、失败降级 | 需要配置 Embedding 服务才能建语义索引；可用词法检索降级；未做大型语料性能承诺，详见 [持久化故事检索](RAG_STORAGE.md) |
| 故事问答 | 本地摘录及 AI 证据回答；章节、doc_id、逐字引用；无效引用拒绝采纳 | 出处有效不等于答案被逻辑蕴含；AI 无答案判断仍需评估 |
| 剧情联动 | 指定场末变更 → 影响计划 → 逐场改写/检查 → 候选差异 → 采用或回退；历史约束保留 | 见下文事件能力；当前不增删/重排场景，不做多分支合并 |
| 事件推理 | 类型与前提检查、三值状态、原子更新、来源证明、场景依赖、反事实影响、历史快照 | 推理针对已表达的账本；不能证明模型没有漏提自然语言事件 |
| 自定义事件（本轮新增） | 用户用自然语言描述；模型编译额外状态、前提、内置步骤和效果；预览确认后执行；规则随版本保存 | 支持有限枚举状态和显式组合步骤，不能输入任意程序；详见 [自定义事件](CUSTOM_EVENTS.md) |
| 剧情版本与恢复 | SQLite 保存计划、原稿、候选、证明和检查点；预算累计；初始事实/规则冻结；采用前重检与哈希保护 | 浏览器可恢复上次任务；旧无账本计划要重新预览；不能把恢复说成任意检查点编辑 |
| 改编 Agent | 受控规划、工具注册表、审校/修改循环、短期记忆压缩、历史会话保存、预算与无效调用限制 | 本地演示策略和 AI 规划两种模式；不等于通用自治代理 |
| 多角色协作 | 主管、审校、一致性、改编角色，黑板、消息流、轨迹、会话 | 角色分工与工具流程，部分角色是确定性分析器；不是每个角色都独立运行 LLM 循环 |
| 创作图谱（本轮新增） | 场景开始/结束状态、关系图、事件时间线、来源跳转、角色筛选；当前/候选/原稿对照 | 未核验编辑不冒充已确认关系；同场虚线不代表亲疏 |
| 风格模板（本轮新增） | 六个起始模板、自定义语气/节奏/保真/补充要求、不可变模板版本、随剧本快照 | AI 转换/润色/剧情改写使用；本地模式只记录偏好 |
| 幕集组织（本轮新增） | 均匀或 AI 建议分幕/分集、标题/边界编辑、目标分钟、场景树 | 保持场景 ID 与原顺序；不增删合并场景 |
| 情绪与朗读（本轮新增） | 原有标注轨迹、AI 当前场景情绪解释、证据；每角色/旁白声线、语速/音高/音量、暂停继续 | 设备浏览器语音试听，不生成 MP3；未标注不猜测 |
| 模型配置与指标 | 多供应商配置切换/测试、兼容请求协议、超时/限流/重试、缓存、成功率、延迟、Token、任务指标 | 没有计价配置时不虚构费用；可选 Redis 全局请求速率限制，尚无多用户/Token 配额 |
| REST 与 MCP | Web 共用 REST；MCP 提供导入、转换、场景访问、局部重写、审校、知识检索和 Agent 等工具 | 剧情规则的新接口目前是 REST/Web，尚未封装为 MCP 剧情编辑工具 |
| 工程验证 | pytest、Ruff、离线固定管线/单 Agent/多角色对比、对白诊断、独立 RAG 评测和门禁 | 模拟模型协议测试不代表真实模型创作质量；历史评测日期与批次分开记录 |

## 剧情事件支持范围

原有六类共八种内置操作：死亡 death、离场 exit、复活 revive、回归 return、物品转移 transfer、地点移动 move、获知秘密 learn、关系变化 relationship。内部还有 act、use_item，用来检查正文行动。

现在另有 custom 自定义事件入口，不必为每一种剧情都新增后端枚举。例如：

- 受伤/康复：增加健康状态，受伤时禁止行动，康复后恢复。
- 被捕/获释：增加拘束状态，规则说明谁需要有行动能力和释放条件。
- 销毁/修复物品：增加可用状态，损毁后禁止使用、转交或读取线索。
- 结婚/离婚、身份暴露/伪装变化：定义有对象的双向关系或单体身份状态。
- 背叛并交出钥匙：一个自定义事件组合关系变化与物品转移，后一步失败则整个事件不提交。

这些是可表达的规则模式，**不是自动正确理解所有相应叙事的保证**。模型提出的前提、参与者、效果和行动限制必须在计划中核对；初始假设不能填入后续才发生的事实。原有生死、归属、知情规则仍由内置步骤执行。

## 数据与入口

- `Screenplay`：作品信息、来源章节、全局状态、人物、场景、可选 plot_state。
- `StoryLogic`：实体、初始条件及出处快照、逐场事件与覆盖、自定义属性和规则。
- `RevisionPlan`：已冻结原稿与变更、逐场计划、原稿重放与插入事件后的推演。
- `ScriptRevision`：候选、原稿、差异、规则证明、问题、预算和结果哈希。

常用 REST 入口：`/api/convert/jobs`、`/api/scenes/chat`、`/api/scenes/review`、`/api/rag/query`、`/api/rag/answer`、`/api/plot/plan`、`/api/plot/logic/check`、`/api/plot/plans/{id}/logic`、`/api/plot/jobs`、`/api/plot/revisions/{id}/adopt` 与 `/rollback`。完整参数看运行服务的 `/docs`。

核心文件：`src/story2script/logic_models.py`、`logic_engine.py`、`custom_events.py`、`logic_integration.py`、`plot_revision.py`、`plot_api.py`；前端 `static/plot.js`。其余模块在 README 对应章节列出。
