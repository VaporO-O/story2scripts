## 对白实现改进

- 一个场景保留全部有依据的对白，解除只取第一句及 100 字上限。
- 区分“林夏对周宁说”中的说话人和听话人；未知说话人的“他对周宁说”不强行归给周宁。
- 识别后置说话人、短回答及相邻的多轮对白；补全只有后置言说标签的人物识别。
- AI 转换提示词携带原文明确的说话人证据；对于完整原句一致且归属唯一的模型错配，服务端纠正角色 ID。
- 局部重写提示词要求保留关键剧情信息及归属，原句被错误转交给另一人物时同样纠正。合理改述仍允许；没有逐字证据时不自动猜测归属。

新增原创回归集 `evals/datasets/dialogue/v1/`：8 个案例、37 条对白，覆盖多轮、听话人、后置说话人、短回答、长对白和重复原句。使用原提交的源码快照生成旧结果，再用同一新版评分函数比较：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 匹配并正确归属 | 19 / 37 | 37 / 37 |
| 原句匹配 | 20 / 37 | 37 / 37 |
| 已匹配说话人错误 | 1 | 0 |

这是针对已定位缺陷的本地回归结果，不能外推为真实小说或真实模型的 100% 准确率。集内带 `holdout` 标签的样本在本轮也用于边界排错，因此本表按回归集报告，不作为未见测试集上的泛化结论。已有 10 个案例的离线评测也通过了全部 19 项回归门禁。

剩余限制：代词指代、无言说标签的轮流对话、复杂别名与跨段引号仍需语义模型处理；AI 重写的信息保真改善尚未用新的真实模型对照实验确认。

## RAG 与故事问答

新增工作台“故事问答”和 `POST /api/rag/answer`：本地模式展示原文摘录；AI 模式基于检索证据生成答案，返回章节、doc_id 和逐字引用。引用不存在、摘录不属于检索片段或没有引用时不采纳答案；模型也可明确表示依据不足。引用校验只能验证出处，不能证明答案的每项推理都正确。

检索改进包括：

- 可选 `lexical`、`embedding`、`hybrid`；AI 自动模式在配置 Embedding 后使用词法和语义的 RRF 融合。
- 融合前过滤允许的章节；相同语义分数使用相同排名，避免 ID 顺序干扰词法证据。
- 混合查询的语义服务失败时保留词法结果并记录降级；评测不把降级结果冒充语义效果。
- 可选 LLM 重排序，只能重排已过滤的候选文档；无效引用回退并提示。
- 摘录根据问题选择窗口，避免答案位于片段末尾却被固定截取前 200 字丢掉。
- 过滤“在、的”等单字虚词导致的无关命中。
- 指定前文范围时屏蔽全书人物/地点摘要，避免摘要透露未来事件。全文问答继续允许全部章节。

本节记录对白与 RAG 初始优化批次；当时的语义向量仅保存在单次请求的内存索引中。后续持久化实现与当前配置见下文“持久化向量索引更新”。

## 持久化向量索引更新（2026-11-17）

故事检索现已使用 SQLite 与 `sqlite-vec` 保存索引清单、小说片段、元数据和 Embedding 向量。相同命名空间、供应商账号、模型版本、分块配置和原文可以复用索引；只对发生变化的新文本生成向量。章节范围在相似度排序前应用，避免未来片段进入候选。词法检索不依赖此向量库。

工作台支持建立、查看和删除持久化索引。SQLite 文件默认放在任务数据库旁的 `story_vectors.db`，也可用 `STORY2SCRIPT_RAG_DB` 指定完整路径。`RAG_STORAGE=sqlite` 为默认持久化模式，`RAG_STORAGE=memory` 可关闭落盘；`RAG_NAMESPACE` 隔离项目/租户索引，默认为 `story2script`；修改 `RAG_EMBEDDING_REVISION` 可在同一模型标识下强制隔离新旧向量。删除索引会删除该索引保存的原文片段和不再被其他索引引用的向量。数据库中保存的是正文分块，部署时应按原文数据的敏感级别管理磁盘权限和备份。

Embedding 未配置或请求失败时，系统不会报告持久化建库成功；一般检索请求会回退词法结果并标明降级。索引管理接口、完整环境变量和限制见 [持久化故事检索](RAG_STORAGE.md)。本次持久化功能由隔离 SQLite、模拟 Embedding 与并发测试验证；没有据此宣称真实 Embedding 服务或新的浏览器流程已完成验收。

2026-11-17 回归：Python 3.12 全量测试 728 项通过、5 项跳过；Ruff、章节解析/朗读队列 Node 测试、静态 JavaScript 语法检查和 `git diff --check` 通过。RAG 离线门禁的开发/留出集 Recall@5 均为 1.0，MRR 分别为 0.9722 / 0.9167。

## 复现

建议使用现有 `story2script` Conda 环境。Windows 如遇系统临时目录权限问题，为 pytest 指定一个新建父目录下的独立 `--basetemp`；不要把已有数据目录作为 basetemp。

```bash
story2script-eval run --dataset evals/datasets/dialogue/v1/dev.json --dataset evals/datasets/dialogue/v1/holdout.json --variants fixed_pipeline --report-prefix dialogue-latest

story2script-eval audit-dialogue --checkpoint evals/reports/ai-dev-comparison-v3.checkpoint.json --dataset evals/datasets/v1/dev.json --output evals/reports/dialogue-dev-audit

story2script-eval rag --dataset evals/datasets/rag/v1/dev.json --dataset evals/datasets/rag/v1/holdout.json --output evals/reports/rag-v1

# 需要配置生成与 Embedding 模型，会产生真实 API 调用。
story2script-eval rag --dataset evals/datasets/rag/v1/dev.json --mode ai --variants lexical,embedding,hybrid,hybrid_rerank --answers --output evals/reports/rag-ai
```

真实对照时使用相同模型、文档、top-k 和缓存策略。关闭缓存可设置 `STORY2SCRIPT_LLM_CACHE_DISABLE=1`。目前统计实际调用和 Token，未配置计费单价时不推算费用。没有配置 Embedding 或运行中降级的变体会明确报告不可用并以非零状态退出。
