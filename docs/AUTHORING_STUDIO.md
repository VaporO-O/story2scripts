# 创作面板使用说明

更新日期：2026-11-08。本轮落地五项能力：剧情图谱、多格式导出、改编风格模板、分幕/分集与内联编辑、情绪轨迹与分角色朗读。

生成或载入剧本后，从顶部进入“创作面板”。原有小说转换、故事问答、局部润色和剧情联动继续保留。无需修改现有场景 ID，也不会因分幕而重排剧情。

## 1 剧情时间线 人物关系和证据

在“剧情图谱”中选择场景及“该场开始/该场结束”，查看这个时点的角色状态、关系和已发生事件。关系图支持拖动节点、放大、缩小、重置；点击角色筛选相关场景，点击关系或“追溯来源”查看原文证据及产生状态的事件。

实线表示事件账本中的关系，方向性关系带箭头。虚线只表示此前在同一场景出现，不代表友情或敌意。尚无事件账本时显示出场关系和摘要；存在未核验编辑或规则错误时，不把旧关系标为已确认事实。

事件列表展示前提、实际值、状态后果及上游场景。证据按钮可定位到相应场景的正文段落，引用失效时同时展示保存的原始引文。历史回忆使用引擎的历史快照，不把回忆结果写回当下。场景开始时不会显示该场结尾才建立的敌对等关系。

“查看版本”可切换当前工作稿、最近剧情候选及该候选的原稿。候选和原稿只读；工作稿可以编辑。候选来源于原有“剧情改写”工作流，恢复上次剧情任务后也可使用这项对照。

## 2 TXT HTML Word 与打印

进入“导出与草稿”，可导出当前查看版本的 TXT、HTML、Word。可勾选人物表、场景与道具表。输出保留场景顺序、人物姓名、对白、动作、情绪/表演指示、幕/集标题及目标时长；标题、状态和内容摘要哈希说明导出的是哪一份版本。

Word 使用可编辑段落，包含中文字体、场景标题、对白缩进、页码与附表。HTML 是独立文档，不需要工作台脚本；“打开打印预览”打开排版后的 HTML，使用浏览器打印即可保存 PDF。**当前没有后台直接生成 PDF 或音频文件的接口。**

导出不会采用剧情候选，也不改变工作稿。未核验编辑会标“草稿 待重新核验”；有事件账本时重新运行规则，不能仅靠旧的通过标记输出“规则通过”。没有账本则标明未建立事件账本。正文内容做文本/HTML 转义，不执行小说或对白里的脚本。

## 3 改编风格模板

在工作台小说输入区展开“改编风格与节奏”。内置忠实改编、悬疑追索、人物喜剧、短剧钩子、情感留白、舞台对峙六个起始模板。可调语气氛围、节奏、表达保真和补充要求。

“保存为模板版本”将配置保存到本机数据库；自定义模板后续保存生成新版本，旧版本保留。“应用到当前剧本”保存创作偏好快照，供之后 AI 局部润色和剧情改写使用，不会立即重写现有正文。新全文转换同时接收所选偏好。

本地转换只保存偏好，不伪装成理解了风格要求。AI 模式把这些偏好作为创作数据纳入提示；它们不能覆盖输出 Schema、对白归属和已确认剧情约束。表达扩展档也不等于可以绕过剧情变更流程修改重大事实。

## 4 分幕 分集与内联编辑

在“分幕与编辑”选择“幕”或“集”、数量、可选目标分钟数，以及均匀分组或 AI 按叙事转折建议。先预览，再调整每组标题和结束场景，最后应用。每套分组必须连续、完整、无重复地覆盖原场景；幕与集可以同时存在，各自独立分组。

均匀分组只是便于组织的起点，不声称识别了故事高潮。AI 分组只读场景摘要、节拍和冲突并建议分界，不改正文；输出同样受到完整覆盖和顺序校验。目标分钟数是作者目标，不是自动估计片长。当前不支持增删、合并、重排场景。

场景树可定位各幕/集下的场景，角色筛选缩小列表。编辑表单可修改地点、昼夜、概要、目标、冲突、节拍、潜台词、动作、对白、说话人、表演指示与情绪。地点/内外景/昼夜会同步更新场景标题。工作台的场景预览中也有“编辑场景正文”按钮。

停止输入 2 秒后自动保存；“立即保存场景”或 Ctrl+S 可马上保存。切换创作子面板、场景、导出前会先提交尚未保存的编辑。场景 ID、来源章节、历史时间锚点不允许通过内联编辑改变。

正文/场景语义变化会清除旧审校结论，并写入 `editing.status: needs_check`。旧事件账本保留用于对照，不能直接当作最新正文已通过检查。直接改 YAML 后点击校验，也会比较上次工作稿并标记变更。

- “检查现有事件账本”不调用模型，可以指出引用失效或规则冲突，但不能仅因此清除待核验标记。
- “AI 重提事件并核验”对改动场景重新提取事件，冻结初始事实与规则，再进行全剧语义检查。成功后标为 checked；失败仍保持草稿状态。
- 没有事件账本时，AI 检查只完成语义审校，不能称作确定性因果证明；建立账本仍使用剧情改写预览。

如果要改变事件事实并联动后续剧情，继续使用“剧情改写”，不要用局部润色假装整个下游已经同步修复。

## 草稿与历史

“导出与草稿”可保存、另存、列出草稿及历史版本。保存在现有 SQLite 任务数据库，使用 `STORY2SCRIPT_JOBS_DB`，不需要新增数据库服务。

每次保存使用版本号进行冲突检查；其他窗口先保存时不会静默覆盖它。可载入最新草稿或历史版。历史版下次保存为独立草稿，原历史保持可恢复。载入别的草稿前，当前工作稿先保存；未校验的源码会提示先处理。

模板、幕集、编辑状态随 YAML 保存，旧剧本默认没有这些字段，仍可读取；哈希计算忽略空的新字段，兼容已有剧情版本。

## 5 情绪轨迹与分角色朗读

“读取全剧情绪标注”展示对白已有的 emotion 字段。没有标注就显示未标注，不根据标点强行猜测。角色可按场景查看情绪序列及对应原话、表演指示。

“AI 分析当前场景情绪”产生单独的解释报告，不修改正文和剧情账本。返回项必须完整覆盖所选对白、保持原说话人、引用完整原句；遗漏、重复或假引用会拒绝。剧本更新后旧分析失效，不继续展示成最新结果。

朗读使用浏览器 Web Speech 的设备声线，支持旁白与每个角色分别选声线、语速、音高、音量，选择当前场景或完整剧本、包含或跳过动作旁白，并提供暂停/继续/停止。声线选择保存在本浏览器，长文本按 Unicode 字符分段，保留原字词和角色顺序。剧本或查看版本变化时停止旧队列。

声线数量、是否本地合成和发音效果取决于设备/浏览器；界面会标注本地声线与无声线情况。这里提供试听，不提供 MP3 下载、云声线克隆或人物音色训练。本轮用音量 0 验证播放生命周期，没有用大音量影响用户休息，也没有进行音质主观验收。

## 后台 AI 任务

AI 分幕、情绪分析与编辑后重检现在先创建后台任务，再显示进度。顶部可恢复上次创作任务、查看历史、继续中断任务和取消排队任务；结果与原稿单独保存，不覆盖后续编辑。默认 80 次调用、1200 秒累计执行时间，最多执行三次，已保存模型响应在恢复时复用。详见 [TASK_LAYER_GUIDE.md](TASK_LAYER_GUIDE.md)。

## HTTP 与数据模型

| 接口 | 用途 |
| --- | --- |
| GET/POST /api/studio/templates | 读取模板/新增不可变模板版本 |
| POST /api/studio/projection | 按场景开始或结束投影事实、关系、事件、来源 |
| POST /api/studio/structure | 均匀分组立即返回；AI 返回 202 任务状态 |
| POST /api/studio/edit | 更新场景、结构或创作偏好；标记需核验正文 |
| GET/POST /api/studio/drafts | 列出/保存草稿，expected_version 检查冲突 |
| GET /api/studio/drafts/{id} | 读取草稿，version 参数可读历史快照 |
| GET /api/studio/drafts/{id}/versions | 读取历史版本目录 |
| POST /api/studio/recheck | 规则重放立即返回；AI 返回 202 任务状态 |
| POST /api/studio/emotions | 读取标注立即返回；AI 返回 202 任务状态 |
| POST/GET /api/studio/jobs | 创建后台任务/查询历史，另有状态、原稿、恢复与取消子接口 |
| POST /api/studio/export | 导出当前 yaml_text 的 txt/html/docx |

Screenplay 新增可选 `creative_brief`、`structure`、`editing`。转换请求新增 creative_brief。源码校验可提供 previous_yaml 以识别变更，并返回归一化的 yaml_text。浏览器朗读无需新增语音服务器或 API Key。

本轮验证记录见 [AUTHORING_VALIDATION.md](AUTHORING_VALIDATION.md)。AI 创作质量、分幕合理性和情绪解释准确率尚未做真实模型评测，协议与版本保护测试不能替代这些评测。
