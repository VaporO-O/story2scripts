# Story2Script 真实 AI 对照评测报告

## 结论

`dev` 与 `holdout` 两轮真实模型评测都不支持把多 Agent 设为所有任务的默认模式。

- 多 Agent 的平均最终分在 `dev` 上高 `0.1554`，在 `holdout` 上仅高 `0.0333`；两轮的
  单 Agent / 多 Agent 95% 置信区间都重叠。
- 多 Agent 的目标达成率分别高 `13.33` 和 `20.00` 个百分点，说明它在质量阈值优先的
  场景仍有价值。
- 对应代价稳定存在：多 Agent Token 为单 Agent 的 `1.6893x`（dev）和 `1.6997x`
  （holdout），LLM 调用为 `1.7230x` 和 `1.7778x`。
- 两轮中多 Agent 的对白归属准确率都低于单 Agent：`65.6%` vs `74.4%`（dev），
  `68.9%` vs `74.4%`（holdout）。
- `dev` 的 AI 辅助匿名盲评以 `9:6` 偏向多 Agent，但 95% Wilson 区间跨过 `50%`；
  `holdout` 盲评材料已经生成，尚未由独立评审者填写。

因此，Story2Script 默认使用单 Agent；对于修改价值高、允许更高延迟和 Token 消耗的复杂
任务，可由用户选择多 Agent 质量优先模式。`holdout` 确认了这个产品决策，没有提供把多
Agent 切为默认模式的新证据。

## 实验协议

两轮评测均使用 `gpt-5.6-sol`、`true-sota.com` Responses API、`high` 推理配置，关闭
LLM 响应缓存。每轮包含 5 个 case，每个 case 独立采样 3 次，共 15 组结果；单 Agent
上限为 12 步，多 Agent 上限为 6 轮且每个专职 Agent 上限为 12 步，质量阈值为 `8.9`。

| 转换失败 | 0 | 0 |

`dev` 报告记录的基线提交为 `f42ba0c`；包含该轮评测实现与对应 Prompt 内容的完整提交为
`452e821`。`holdout` 运行绑定提交 `2f68bae`。报告同时记录 8 个业务 Prompt 的稳定 ID
和 SHA-256 内容指纹，用于发现 Prompt 漂移。

这里比较的是两种 Agent 方案在各自固定循环上限下的自然质量与资源消耗，不是等额 Token
上限实验。

15/15 个 case-sample 都成功落盘，没有转换失败。单 Agent 有 3 次在 12 步上限处结束为
`budget_exhausted`；这是评测协议定义的有效工作流状态，因此计入 80% 工作流完成率，而
不是运行失败或缺失样本。

`holdout` 的多 Agent 最终分只比单 Agent 高 `0.0333`，但目标达成率高 `20.00` 个百分
点；其 Token、LLM 调用和平均延迟分别为单 Agent 的 `1.6997x`、`1.7778x` 和
`1.4410x`。质量置信区间仍然重叠，不能把 `0.0333` 的观测差异解释为稳定质量优势。

## 并行运行效率

`holdout` 按 case 分成 5 个独立进程，每个进程负责 1 个 case 的 3 次重复。实际墙钟时间
约 `46.76` 分钟；把 15 组报告中的转换、固定管线、单 Agent 和多 Agent 耗时相加，串行
等价时间为 `193.03` 分钟，对应 `4.13x` 提速。

进程隔离保证各分片拥有独立的全局 metrics 单例，Token 归因不会互相清零。合并器在生成
终版报告前校验 Git 提交、数据指纹、运行配置、case/sample 完整性与唯一性。

并行运行下的延迟是 5 个进程共同施压网关时的单任务耗时，不能与 `dev` 串行运行的绝对
延迟直接比较。Token、调用次数、质量分和达成率不受这一解释边界影响。

## 匿名盲评

评测器用固定随机种子隐藏单 Agent 与多 Agent 的候选来源。评审过程中只提供原文、候选
A/B 和以下 Rubric，不提供答案密钥：

1. 剧情信息是否忠于原文
2. 场景是否可拍摄且动作明确
3. 对白是否推动目标与冲突
4. 人物语气与跨章状态是否一致
5. 整体成稿是否需要更少人工修改

2026-08-10 完成了一次 `dev` 独立 AI 辅助盲评，15 对全部填写且评分器未报告错误：

| 结果 | 数量 | 不含平局偏好率 |
| --- | ---: | ---: |
| 单 Agent | 6 | 40.0% |
| 多 Agent | 9 | 60.0% |
| 平局 | 0 | - |

多 Agent 偏好率的 95% Wilson 区间为 `35.7%–80.2%`，跨过 `50%`。这说明结果方向偏向
多 Agent，但不能据此宣称稳定胜出。评审者为 AI，不属于人类用户研究，也不能替代真实
人工盲评。

`holdout` 已生成 `blind-review`、空白 `blind-responses` 和独立 `blind-key` 文件，但未
额外调用外部模型填写答卷。因此本报告只使用自动评测确认原结论，不把尚未发生的盲评写成
证据。

## 成本解释

两轮运行都未配置供应商的输入、输出 Token 单价，因此不虚构金额成本。稳定复现的资源
消耗差异已经足以否决“所有任务默认多 Agent”；它同时允许把多 Agent 作为用户主动选择的
质量优先模式。

## 结果边界

- 当前比较采用固定步骤/轮次上限，没有对单 Agent 和多 Agent 强制相同的总 Token 上限。
- 金额成本需要供应商实际计费单价，不能从模型名称推断。
- `dev` 的 15 对 AI 辅助盲评只提供方向性证据；`holdout` 尚未完成独立盲评。
- 默认策略若要再次变更，仍应以更大样本和真实人工盲评为准。

原始报告、checkpoint、候选剧本、匿名答卷和答案密钥保存在被 Git 忽略的
`evals/reports/` 中，避免把评测源文本和受保护映射提交到公开仓库。
