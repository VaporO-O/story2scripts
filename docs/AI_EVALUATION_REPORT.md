# Story2Script 真实 AI 对照评测报告

## 结论

当前证据不支持把多 Agent 设为所有任务的默认模式。

- 多 Agent 在自动评测中的平均最终分比单 Agent 高 `0.1554`，目标达成率高 `13.33` 个百分点。
- AI 辅助匿名盲评中，多 Agent 以 `9:6` 获得更多偏好。
- 对应代价是 `1.4757x` 平均延迟、`1.6893x` Token 和 `1.7230x` LLM 调用。
- 多 Agent 与单 Agent 的自动评分置信区间重叠；15 对盲评样本也不足以证明稳定优势。
- 多 Agent 的对白归属准确率为 `65.6%`，低于单 Agent 的 `74.4%`。

因此，Story2Script 默认使用单 Agent；对于修改价值高、允许更高延迟和 Token 消耗的复杂任务，可由用户选择多 Agent 质量优先模式。

## 自动评测

| 方案 | 工作流完成率 | 目标达成率 | 最终分（95% CI） | p50 / p95 延迟 | 总 Tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定管线 | 100.0% | 0.0% | 6.905（6.717–7.094） | 15.8s / 19.5s | 264,469 |
| 单 Agent | 66.7% | 66.7% | 8.889（8.732–9.047） | 313.7s / 772.2s | 1,838,061 |
| 多 Agent | 86.7% | 80.0% | 9.045（8.957–9.132） | 386.2s / 925.1s | 3,105,013 |

单 Agent 和多 Agent 使用相同数据集、模型、Prompt 快照、采样次数和各自固定的循环上限。这里比较的是两种方案在自然运行预算下的质量与资源消耗，不是等额 Token 上限实验。

## 匿名盲评

评测器用固定随机种子隐藏单 Agent 与多 Agent 的候选来源。评审过程中只提供原文、候选 A/B 和以下 Rubric，不提供答案密钥：

1. 剧情信息是否忠于原文
2. 场景是否可拍摄且动作明确
3. 对白是否推动目标与冲突
4. 人物语气与跨章状态是否一致
5. 整体成稿是否需要更少人工修改

2026-08-10 完成了一次独立 AI 辅助盲评，15 对全部填写且评分器未报告错误：

| 结果 | 数量 | 不含平局偏好率 |
| --- | ---: | ---: |
| 单 Agent | 6 | 40.0% |
| 多 Agent | 9 | 60.0% |
| 平局 | 0 | - |

多 Agent 偏好率的 95% Wilson 区间为 `35.7%–80.2%`，跨过 `50%`。这说明结果方向偏向多 Agent，但不能据此宣称稳定胜出。评审者为 AI，不属于人类用户研究，也不能替代真实人工盲评。

## 成本解释

本次运行未配置供应商的输入、输出 Token 单价，因此不虚构金额成本。实测资源消耗显示：

- 多 Agent 总 Token 是单 Agent 的 `1.6893x`。
- 多 Agent 平均延迟是单 Agent 的 `1.4757x`。
- 多 Agent LLM 调用次数是单 Agent 的 `1.7230x`。

在质量优势尚不确定时，这组成本数据足以否决“所有任务默认多 Agent”；但它仍允许把多 Agent 作为用户主动选择的质量优先模式。

## 结果边界

- 真实模型评测只运行了 `dev` 集，尚未用 `holdout` 集做最终确认。
- 当前比较采用固定步骤/轮次上限，没有对单 Agent 和多 Agent 强制相同的总 Token 上限。
- 金额成本需要供应商实际计费单价，不能从模型名称推断。
- 15 对 AI 辅助盲评只提供方向性证据，默认策略变更仍应以真实人工盲评为准。

原始报告、checkpoint、候选剧本、匿名答卷和答案密钥保存在被 Git 忽略的 `evals/reports/` 中，避免把评测源文本和受保护映射提交到公开仓库。
