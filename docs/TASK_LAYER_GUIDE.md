# 本地后台任务与恢复

更新日期：2026-11-08。本文件记录默认 SQLite + 线程池任务层。后续已增加可选 Redis/Celery 模式，见 [Redis 使用说明](REDIS_GUIDE.md)；本文件中的进程内订阅说明适用于 local 模式。

## 已完成的改变

- 任务先落盘再进入执行队列；存储失败返回 HTTP 503，不降级成没有持久化保障的内存任务。
- 状态与结果写入成功后才更新内存、发布进度/完成事件。终态不能被迟到的进度或错误回调回退；损坏的成功结果也不会继续报告成功。
- SQLite 增加 revision 和 idempotency_key，旧任务表自动迁移。状态变更使用版本条件更新，避免旧状态覆盖新状态。
- 相同任务类型和 Idempotency-Key、相同请求返回同一个 job_id；同标识不同内容返回 409。未提供标识时允许创建新的任务，便于用户主动重新生成。
- 同一主机用 OS 文件锁保护正在执行的 job_id；重复恢复器不会同时执行同一个任务。进程退出后锁由 OS 释放，下次启动可领取未完成任务。
- AI 分幕/分集、AI 情绪分析、编辑后 AI 重提事件和全剧核验，接入可恢复后台任务，拥有独立状态与已保存结果。

## 在工作台使用

“创作面板”顶部增加“后台创作任务”。原来的 AI 操作按钮会先提交任务，再显示阶段进度、调用次数、累计执行时间、执行尝试次数。任务运行时可切换面板；任务输入在提交时冻结，之后的草稿编辑不会改变它。

刷新页面或断开浏览器连接后，可点“恢复上次创作任务”。服务器继续运行时任务会继续执行；服务器也重启时，未完成任务由本地恢复器接续执行。浏览器仅保存任务 ID/请求标识，不需要把小说全文写入 localStorage。也可从“任务历史”选择此前任务。

恢复出的结果不会直接覆盖工作稿：

1. 若当前工作稿与任务原稿一致，点击“查看或应用任务结果”。分幕结果仍需预览分界后确认，情绪结果展示为报告，重检结果载入后保存草稿。
2. 若当前内容已变化，界面阻止覆盖。可以先保存当前编辑，再“载入任务原稿”查看旧结果。载入动作会先保存已有工作稿；存在未校验源码时先提示处理。
3. HTTP 提交响应丢失时，可以通过同一个请求标识找到已经保存的任务，避免反复点击后创建重复付费任务。

“取消排队任务”只适用于 queued；已开始的模型请求不会被强行中止。“继续中断任务”适用于失败且未取消的任务，沿用输入、检查点和剩余预算。最多三次执行尝试，含首次、自动恢复和手动继续。

## 检查点与预算

创作任务在每次模型调用前保存累计调用次数，在返回可解析结果后保存响应检查点。恢复时以完整提示、Schema 和上下文摘要匹配响应，已保存且仍可用的响应不重复调用模型。

重检任务按场景执行：已完成的提取步骤在恢复时重放，随后继续未完成场景和全剧审校。若响应虽通过结构校验，但引用/覆盖/场景身份等业务校验失败，会移除该响应检查点，以便在剩余预算内重新尝试。此前成功步骤保留。

最终结果先写检查点，再提交任务终态。因此“结果已算出但终态写失败”恢复时无需重新生成。调用数、执行时间和尝试次数均不因恢复而清零；排队时间不算模型执行预算。

进程在模型请求进行中退出时，无法知道该次实际运行了多久。检查点会保留该次请求的时间预留；恢复时按预留上限保守计入时间预算，避免通过反复重启退还未知耗时。正常返回或异常被捕获时按实际已记录执行时间计算。

默认创作任务最多 80 次模型调用、1200 秒累计执行时间，页面可调整。HTTP 同步本地功能仍立即返回。模型超时使用现有客户端及剩余预算；不是能强杀任意阻塞代码的硬超时。

模型请求发出后、响应尚未可靠保存前进程退出，恢复仍可能重发请求。远端是否已经完成和计费无法由本地数据库判断，因此不承诺绝对不重复调用或计费。

## 状态与错误

| 状态/返回 | 含义 |
| --- | --- |
| queued | 已保存、等待线程执行 |
| running | 已领取并执行中 |
| succeeded | 结果已经可靠保存。重检 valid=false 仍是“检查执行完成”，但剧情未通过 |
| failed | 执行中断或业务失败；阶段为已取消时代表排队取消 |
| HTTP 422 | 输入非法、无法取消运行任务、达到恢复上限等 |
| HTTP 409 | 去重标识内容冲突或状态版本竞争 |
| HTTP 503 | 数据库存储/读取或执行器暂不可用；不能当成成功 |

数据库暂时不可访问时，状态接口明确报错。后台存储故障会停止当前工作；存储恢复后可记录失败并恢复任务。如果服务启动时数据库不可用，API 保留错误说明，后续请求会重试恢复，而不是偷偷运行内存任务。

取消保持既有 API 的 failed + 已取消 表达，避免破坏旧前端状态枚举。当前只对同主机本地数据库提供执行互斥，仍建议单 Web 服务进程部署：各进程的 SSE 订阅不共享，不能因此宣称已实现分布式任务系统。

## 接口

| 方法与路径 | 行为 |
| --- | --- |
| POST /api/studio/jobs | 提交 operation、parameters、max_calls、timeout_seconds，返回 202 与 job_id |
| GET /api/studio/jobs/{id} | 状态、进度、预算、尝试次数与成功后的结果 |
| GET /api/studio/jobs | 创作任务历史，不返回整篇输入或结果 |
| GET /api/studio/jobs/requests/{key} | 按提交请求标识恢复 job_id，处理响应丢失 |
| GET /api/studio/jobs/{id}/input | 读取任务冻结的原稿与参数 |
| POST /api/studio/jobs/{id}/resume | 继续中断任务，返回 202 |
| POST /api/studio/jobs/{id}/cancel | 取消排队任务 |

提交例子：

```http
POST /api/studio/jobs
Content-Type: application/json
Idempotency-Key: a-unique-key-for-this-user-action
```

```json
{
  "operation": "recheck",
  "parameters": {"yaml_text": "...完整剧本...", "mode": "ai"},
  "max_calls": 80,
  "timeout_seconds": 1200
}
```

operation 可为 structure、emotions、recheck；parameters 按相应已有请求模型校验。重检至少需要足够预算覆盖待提取场景和最终审校。

兼容入口 `/api/studio/structure`、`/emotions`、`/recheck`：AI 模式现在返回 **202 任务状态**，外部客户端需轮询 jobs 接口取结果；balanced/annotated/rules 本地模式继续返回 200 原响应。Python 内部业务函数保持直接调用能力，测试和后台任务共用逻辑。

转换、Agent、协作和剧情的创建接口也支持可选 Idempotency-Key，保持原有成功响应结构。成功提交后再次使用相同标识，不会自动重跑失败任务，恢复应使用恢复入口，或使用新标识明确发起新任务。

## 部署与验证

仍使用 `.story2script/jobs.db`（可用 STORY2SCRIPT_JOBS_DB 指定）和每类任务的本地线程池（STORY2SCRIPT_JOBS_WORKERS，默认 2）。数据库旁会建立 `<数据库文件名>.locks` 目录保存小型锁文件；不要在任务运行时移动数据库或锁目录。恢复不需要手工删除锁文件，OS 锁会随进程退出释放。

本轮没有把转换管线和 Agent 每一步全部改造成断点任务：它们保留已有的任务级恢复；剧情改写保留已有逐场检查点，创作任务新增逐响应检查点。后续 Redis/Worker 阶段已加入共享队列、缓存和限流，支持同主机独立进程；跨机器业务数据库尚未迁移。

验证详情见 [TASK_LAYER_VALIDATION.md](TASK_LAYER_VALIDATION.md)。核心代码为 job_store.py、job_lock.py、studio_jobs.py、studio_tasks.py、studio_api.py、static/studio.js；本轮测试覆盖真实子进程退出、并发重复提交、存储失败、结果恢复和前端版本保护。
